# pili:// 协议安装包 · 安装记录（留档）

版本：2026-11-17
适用：Windows 10 / 11，PowerShell 5.1（系统自带）
权限：**不需要管理员**。只写 `HKCU\Software\Classes\pili` 和 `%LOCALAPPDATA%`。

---

## 1. 包内文件

| 文件 | 作用 |
| --- | --- |
| `安装.cmd` | 双击安装入口（ASCII，避免代码页问题） |
| `自检.cmd` | 双击重跑自检，不重新安装 |
| `卸载.cmd` | 双击卸载（会二次确认） |
| `install-protocol.ps1` | 安装 / 自检 / 卸载的主脚本 |
| `pili-play.ps1` | `pili://` 协议处理脚本：解析参数、请求后端、启动 mpv / PotPlayer |
| `pili-launch.vbs` | 无窗口启动器：`wscript` 隐藏拉起 PowerShell，避免闪黑框 |
| `使用说明.txt` | 给使用者看的简短说明 |
| `安装记录.md` | 本文件，留档用 |

安装脚本按**自身所在目录**找 `pili-play.ps1` / `pili-launch.vbs`，不写死绝对路径；
目录含空格、中文都可以（所有路径都加了引号，注册表 command 同样带引号）。

## 2. 安装时实际写入的文件

脚本会把两个运行时文件复制到固定目录，之后安装包可以移动或删除：

```
%LOCALAPPDATA%\pili4k\bin\pili-play.ps1
%LOCALAPPDATA%\pili4k\bin\pili-launch.vbs
```

运行时还会在 `%LOCALAPPDATA%\pili4k\` 下生成：

```
play.log            每次 pili:// 调用的日志（含 DEDUPE / TITLE / CMD / STARTED）
play.log.1          超过 1MB 后的上一份
mpv.log             mpv 自身日志
mpv-path.txt        安装器检测到的 mpv 路径（播放时优先读取）
launch-guard.txt    5 秒同目标冷却标记（防连点拉起多个播放器）
```

日志目录可用环境变量 `BILI4K_LOG_DIR` 覆盖。

## 3. 注册表内容（HKCU，当前用户）

注册表路径：`HKEY_CURRENT_USER\Software\Classes\pili`

```reg
Windows Registry Editor Version 5.00

[HKEY_CURRENT_USER\Software\Classes\pili]
@="URL:Bili 4K Play Protocol"
"URL Protocol"=""

[HKEY_CURRENT_USER\Software\Classes\pili\DefaultIcon]
@="C:\\Windows\\System32\\shell32.dll,1"

[HKEY_CURRENT_USER\Software\Classes\pili\shell\open\command]
@="\"C:\\Windows\\System32\\wscript.exe\" //nologo \"C:\\Users\\<用户名>\\AppData\\Local\\pili4k\\bin\\pili-launch.vbs\" \"%1\""
```

要点：

- `URL Protocol` 为空字符串，是自定义 URL 协议能被浏览器调用的必要条件。
- `command` 用 `wscript.exe` + VBS，启动 PowerShell 时 `SW_HIDE`，不会闪控制台窗口。
- `%1` 必须带引号，`pili://` 链接里的 `&` 才不会被截断。
- HKCU 的 `Software\Classes` 会合并进 `HKEY_CLASSES_ROOT`，**当前用户优先于 HKLM**，
  所以不需要提权；如果机器上还有旧的 HKLM 注册，也不会和本安装冲突（HKCU 生效）。

## 4. 安装后的自检项

`安装.cmd` 完成后、以及每次 `自检.cmd`，都会在窗口里逐项打印：

| 检查项 | 判定方式 |
| --- | --- |
| 安装文件 | `pili-play.ps1`、`pili-launch.vbs` 是否存在于 `%LOCALAPPDATA%\pili4k\bin` |
| 注册表 | `command` 是否与「当前启动器路径」逐字一致；`URL Protocol` 是否存在 |
| 调用链 | 用与注册完全相同的参数执行 `wscript → VBS → pili-play.ps1 "pili://check"`，轮询日志出现 `CHECK: handler ok`（最长 12 秒） |
| mpv | 见第 5 节，三种结果分别输出 OK / WARN |

窗口最后固定输出「结论：安装成功 / 有 N 项需要留意 / 失败 N 项」，并附带日志路径、
安装位置、注册表位置，方便直接截图。

退出码：`0` 正常（含 mpv 缺失的警告），`1` 有硬性失败。

## 5. mpv 检测

按以下顺序找，去重后逐个真实启动 `mpv --version`（5 秒超时）：

1. 环境变量 `BILI4K_MPV` 指向的路径
2. PATH 里的 `mpv.exe` / `mpv.com`
3. 常见位置：`Program Files\mpv`、`Program Files (x86)\mpv`、
   `%LOCALAPPDATA%\Programs\mpv`、`scoop\shims`、`scoop\apps\mpv\current`、
   `WinGet\Links`、`Chocolatey\bin`
4. `Program Files` / `Program Files (x86)` / `%LOCALAPPDATA%\Programs` 下名字含 `mpv` 的一级目录

找到可用 mpv 后，安装器会把该路径写进 `%LOCALAPPDATA%\pili4k\mpv-path.txt`。

**播放时**（`pili-play.ps1` 的 `Find-Mpv`）顺序为：
`BILI4K_MPV` → `mpv-path.txt` → PATH → 常见位置。
加这个文件是为了绕开一个坑：环境变量是进程启动时的快照，浏览器如果在设置变量之前
就已启动，它拉起 `wscript → powershell` 时拿不到 `BILI4K_MPV`，于是自检（新进程）通过、
点播放（浏览器拉起）却报「未找到 mpv」。读文件则不受快照影响。

三种结论：

- **找到且能跑**：打印路径、来源和版本首行。
- **没找到**：提示 `winget install mpv` / `scoop install mpv` / 解压官方包，
  或设置 `BILI4K_MPV` 后重跑「自检.cmd」。协议本身仍可用。
- **找到但打不开**：打印进程启动错误或退出码，并给出排查方向：
  手动运行 `mpv --version` 看报错、VC++ 2015-2022 x64 运行库、位数不匹配、
  杀软隔离、改用 PotPlayer 代理模式。

## 6. 卸载干净

双击 `卸载.cmd`，输入 `y`。等价于：

```powershell
Remove-Item -LiteralPath "HKCU:\Software\Classes\pili" -Recurse -Force
Remove-Item -LiteralPath "$env:LOCALAPPDATA\pili4k\bin" -Recurse -Force
Remove-Item -LiteralPath "$env:LOCALAPPDATA\pili4k\mpv-path.txt" -Force
```

日志默认保留，需要彻底清空时再删：

```powershell
Remove-Item -LiteralPath "$env:LOCALAPPDATA\pili4k" -Recurse -Force
```

如果检测到 `HKLM\Software\Classes\pili`（更早的机器级安装），卸载窗口会提示；
删除它需要管理员权限：

```powershell
Remove-Item -LiteralPath "HKLM:\Software\Classes\pili" -Recurse -Force
```

## 7. 维护 / 升级

- 改了 `pili-play.ps1` 或 `pili-launch.vbs`：重新双击 `安装.cmd` 覆盖
  `%LOCALAPPDATA%\pili4k\bin` 下的副本即可；注册表不用动。
- 只想确认当前状态：双击 `自检.cmd`。
- 安装包目录位置随意；注册表只认 `%LOCALAPPDATA%\pili4k\bin`。
